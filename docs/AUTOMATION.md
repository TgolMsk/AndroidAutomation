# 自动化扩展架构

## 边界

`packages/desktop` 是独立的 AVD 多开管理器应用，负责实例、SDK、ADB 和画面。`apps/wanlong-assistant` 是独立的万龙助手应用；两者通过 `@avdm/core` 和本机 `~/.avdm` 共享实例，不通过彼此的 Electron 窗口转发命令。自动化层只通过 `DevicePort` 操作一个**已运行**的实例，不接管模拟器进程，也不依赖 MuMu/雷电的端口或窗口。一次运行绑定实例 index；每次开始时由 `@avdm/core` 解析当前 ADB serial，不能把 `emulator-5556` 等运行时地址写入游戏配置。双应用安装与数据边界见 [双应用架构](APPLICATIONS.md)。

游戏无关的设备端口、模板集读取与视觉匹配放在 `@avdm/automation`；原始 ADB 帧校验留在 `@avdm/core`。`@avdm/emulator-shell` 复用 Electron 主进程、授权 IPC、实时画面与通用组件。助手主进程持有每实例配置、运行状态、取消与实例租约，OpenCV 和游戏流程放在独立工作线程。游戏逻辑放在自动化包的独立游戏模块中，例如 `wanlong/` 的采集状态机；相应 UI、账号和通知属于助手应用。后续游戏通过相同端口接入，可建立并列助手应用；多开管理器不得加入游戏特例。

## 执行约束

1. 每个实例同一时间只允许一个会发送输入的自动化运行。租约在第一个异步操作前取得，并在成功、失败、取消和进程退出时释放。只读探针可单独运行，但不能与写操作共享未同步的截图缓存。
2. 图像识别在独立执行上下文运行，避免 OpenCV 或图像缩放阻塞 Electron 主进程。截图在同一轮识别中复用，模板只加载一次，优先限定 ROI。
3. 游戏包使用显式 `id`、`version`、`packageName`、参考分辨率和配置版本。配置及运行时状态按游戏和实例保存，写入使用原子替换。升级时由游戏包迁移旧配置；未知版本拒绝执行。账号绑定还要核对实例创建标识，避免编号复用时误用旧账号。
4. 默认先做只读探针：确认前台包名、帧尺寸与四个场景锚点分数。写操作需要恰好一个已知画面锚点命中、分数至少 0.90 且比次高分领先至少 0.05；主进程与 worker 均复核，前台切换或未知画面会拒绝。运行记录只保留任务摘要；脚本执行的截图留痕见下文「脚本执行」。
5. 停止请求使用 `AbortSignal` 贯穿等待、截图和设备命令；每个循环有时长、截图数、重试次数及每小时动作数硬上限。应用退出时中止任务并等待清理，模拟器本身保持运行。

## 万龙觉醒迁移

复用 `wanlong-panel` 的模板识别和 `runGatherCycle` G0–G16 状态机，替换旧的 MuMu/雷电驱动、ADB 地址发现和单体 Electron 入口。模板由用户选择本地目录导入或在助手内新建，不把旧仓库的 `.wl-data`、真实游戏截图、登录 XML 或账号资料复制进公开代码或安装包。

旧模板参考分辨率为 2560×1440，当前 #1 为 960×540。两者同为 16:9，但细节缩放会影响分数；探针必须用当前 AVD 的真实画面做正负样本验证。校准失败时需要重新采样模板或调整实例规格，不允许直接进入采集流程。

2026-09-23 的只读验收：#1 实例在 Android 桌面时，前台包名为 `com.android.launcher3`，游戏锚点均未命中。切到万龙觉醒城内主界面后，前台包名匹配，`tpl_nav_map_toggle` 得分 0.943（模板阈值 0.85），另外场景锚点未命中。打包后的 Electron 页面也通过同一实例运行了工作线程探针，显示 960×540、正确包名和 0.943 的命中分数。世界地图实机探针得分 0.978，城内 A 版离线回放最低 0.903，部队面板回放 0.997；兽族 B 版仍缺实帧复核。

单轮写入验收使用 #1 与本机私有模板集，将四种采集资源全部设为禁用：从城内执行 G0 返回世界地图，流程返回 `noResourceWanted`、`dispatched=0`、`captures=2`；截图确认设备停在世界地图。该测试验证了工作线程、ADB RPC、场景门槛、坐标换算、导航输入与状态落盘。它不验证真实派兵、队列 OCR 的全部场景或长期无人值守运行。

## v0.2.0 基线与后续验收

1. 已接入设备端口、只读探针、G0–G16 单轮采集、每实例状态持久化、取消与运行记录。
2. 已接入通用 ETA 调度：显式启停、持久唤醒时间、重启恢复、连续失败退避并在 8 次后暂停。每次唤醒重新运行场景探针和 G0/G1 队列判读，实例租约防止并行输入。
3. 仍需在专用测试账号上验证真实派兵、完整部队面板 OCR、不同分辨率和兽族 B 版；再补失败现场截图、详细日志与配置编辑。
4. 在 v0.2.0 中，旧项目的账号登录、计划编排、统计、Telegram 通知、AI 顾问和模板编辑器尚未移植；双应用版本把这些能力放入 `apps/wanlong-assistant`，具体可用性以对应版本的构建与验收为准。MuMu/雷电驱动由 `@avdm/core` 取代，不再移植。

新增游戏时提供 `GamePlugin`（包名、探针锚点）、游戏配置与状态机，并在相应助手应用的任务注册表中挂接 runner；设备、视觉、调度与实例租约保持共用。任务应先经过假设备回放与真实 AVD 的无派兵验证，再开放派兵配置。

## v0.3.0 助手能力

万龙助手在 `apps/wanlong-assistant` 中实现账号与实例创建时间绑定、交互式登录、模板编辑与校验、采集运行洞察、北京日期统计、异常监控、本地及 Telegram 推送、只读 Telegram 状态/截图查询、AI 画面顾问，以及脚本库和账号任务计划。脚本页可从当前画面截取模板并自动添加点击或等待功能块；模板仍保存在所选本地模板集中，复杂分支保留高级 JSON 编辑。旧脚本与计划 JSON 由 UI 显式导入并校验；旧计划默认关闭自动执行，避免导入后立即触发输入。采集 G0 与部队面板采样认不出界面时先走已校准的游戏更新处理（与 AI 无关，缺更新模板时静默跳过），再问 AI 视觉顾问（默认关闭；脚本执行期间的 AI 介入另受计划配置约束）。「自动处理」（autoActions）另有开关且默认关闭：关着时只记录建议、不点击设备；开着时只执行通过本地风险闸门的关闭 / 取消，以及经过新截图复核、60 秒去重的低风险确认，每次点击前核对实例身份与前台包名、点完必须复验，关闭按钮可自学成模板（每套最多 8 张）。手动的「只读分析」仍只给建议和模板草稿，保存模板前需要用户重新截图核对。

采集、账号登录和脚本计划使用同一实例文件锁；采集调度与脚本计划不再互斥，脚本运行前由计划模块调用 `suspendForScript` 让调度器让路，结束后 15 秒重读队列。异常告警（`apps/wanlong-assistant/src/main/alerts`）取代了原来的只读监控：连续采集失败、恢复阶梯用尽、连续采样失败（掉线）、健康探针发现游戏退出，以及被顶号 / 维护 / 更新公告，默认自动暂停该实例的自动调度（先暂停再推送），留现场截图并按订阅推送到本机通知 / Telegram，处理完在采集总览的暂停横幅上「恢复」。顶号 / 维护 / 更新的识别只用采样或健康探针已经截到的那一帧，命中下限为 max(0.92, 模板阈值)；缺少用户保存的专用模板时静默降级为上面的通用判定。游戏更新需要人工确认、AI 判定操作有风险（「需要人工介入」）在每条链路（到点唤醒、手动一轮 / 刷新、派兵后校准、脚本执行）都走同一个出口：告警模块先暂停再推送，一段异常只告警一次；被告警暂停的实例 AI 不再自动点击。采样认不出界面时先跑顶号探针，命中就不再问 AI。卡死看门狗（画面纹丝不动或截图持续失败、但模拟器进程还在）默认只提醒，「卡死自动重启」（强制冷启动 + 重新拉起游戏 + 熔断）需要在设置里显式开启。机器人默认关闭，只接受同时匹配 Chat ID 和授权用户 ID 的请求：`/status`、`/shot` 由「允许手机查看状态与截图」控制；「允许手机远程操作」默认关闭且单独控制，机器人模块接入按钮回调后才生效。

### ETA 调度（队列驱动）

自动续跑按部队管理面板的倒计时排期：到点先只读采样，队列真有空位才跑一轮 G0–G16；`freeAt = 采样时刻 + 剩余（北京时间 0–9 点疲劳期换算）+ 单程行军`，唤醒取 `freeAt + slack + 抖动`，队列满或读不出按 30/60/120/240/300 秒退避，熔断后 10 分钟再试，另有 3 分钟一次的单帧健康探针。游戏没开时自动用 monkey 拉起并只看不点地等到已知界面；探针门槛之前只允许关弹窗、一次 BACK 与「取消」退出框。采样与采集在每实例常驻的视觉工作线程里运行，模板只编译一次，模板保存 / 删除 / 导入后立即失效重编。调度器的实例锁就是应用外壳的带标签实例租约（占用表、生命周期确认与更新闸门都能看到「正在读取部队管理面板」这类持有者），设备调用走实例的设备通道。账号模块的就绪门槛（基础实例、登录进行中、账号未完成登录检查）拒绝定时唤醒时暂停该实例、不计失败；采集配置跟随绑定的账号；失败现场截图跟随应用设置的留痕策略。接口与钩子见 `apps/wanlong-assistant/src/main/scheduler/README.md`。

## 模板库与视觉引擎（wanlong-panel 模块 c 移植）

- 视觉引擎在 `@avdm/automation`（去底预览、保存时的差分掩码、立即验证、完整编译检查都在一次性模板工作线程里跑）：只用 `TM_CCOEFF_NORMED`；模板灰度标准差 < 12 一律拒绝（`TEMPLATE_LOW_VARIANCE`）；透明底模板按 α 通道生成掩码（cubic 缩放后 ≥128 为不透明，全透明或不透明像素 < 64 / < 10% 拒绝）；模板按内容指纹编译缓存（256 条），阈值与 ROI 每次以调用方为准；ROI 越界、比模板小都返回带中文原因的未命中而不是抛错；`detect()` 一帧批量匹配，单张坏模板只降级为 `found:false`。错误带码（`AppError.code`），经 IPC 信封传到界面。
- 模板保存：裁剪 → PNG → 可选透明底（`alpha`，或 1~3 张差分帧 `diffFrames` 由主进程按与预览相同的算法重算）→ **先过方差守卫再写盘** → `<id>.png` 与 manifest 原子写。固定 ID 覆盖已有模板必须显式 `overwrite: true`（否则 `TEMPLATE_EXISTS`），覆盖时保留清单位置与创建时间。manifest 记录 `std`、`maskCoverage`、`tags`、`note`、`createdAt`、`updatedAt`，读取时一并返回；旧的 `<id>.<随机>.png` 文件名照常读取。
- 旧模板集导入：模板库页「导入 / 合并旧模板集」选择旧面板的 `.wl-data/templates`、`<旧数据目录>/templates` 或单个模板集文件夹，按原版内置播种的规则**只增不改**合并进 `~/.avdm/automation/templates/wanlong/`：没有的模板集整集复制（先图后清单），已有的只补缺的 id，用户改过的模板、AI 自学的模板一个字节不动；用户清单损坏时跳过、绝不覆盖；不安全文件名、缺图、符号链接、其他游戏包名的模板集都跳过并说明原因；所选文件夹里一个模板集都没有时明确提示选错了目录。导入与保存 / 删除同一规则：会补进模板的模板集，绑定它的实例不能在运行，自动续跑先关掉（需要重新探针），写入期间持有设备租约。模板仍不进仓库、不进安装包。
- 模板内容变化（保存 / 删除 / 导入）会推送 `templates-changed {gameId, directory}`，主进程侧用 `AutomationHost.onTemplatesChanged(listener)` 订阅，持有编译缓存的模块（常驻视觉 worker、采样器、资源统计、AI 自学）据此失效。
- 开发者工具 tplkit：`pnpm --filter @avdm/wanlong-assistant run tplkit -- <命令>`（cap / view / analyze / probe / alpha / glyphs / save / verify / cross / ocr / find / scan / ls / del），抓帧走 `@avdm/core`，帧与预览默认写到 `~/.avdm/automation/tplkit`，模板集默认用 `--dir`、`TPLKIT_SET_DIR` 或 `WL_INSTANCE` 绑定的模板集。字形 id 后缀与采集加载器一致（`dig_xxx_0`~`_9`、`colon`、`comma`、`slash`、`dot`、`percent`）。
- 分辨率：模板与字形按 2560×1440 参考坐标。低于参考分辨率的实例截图会被放大后匹配，小图标与数字字形不可靠，模板页会提示；建议把实例建成 2560×1440（至少 1920×1080）再截模板。
## 万龙登录控件

账号登录向导的手机号 / 验证码步骤读取游戏原生 SDK 的 UIAutomator 节点（仅 `com.lilithgames.samo.android.cn` 的节点，重复 id 与无效 bounds 一律拒绝）。每次写入前重新读取界面树，坐标取节点 bounds，不维护固定屏幕坐标。以下 id 均以 `com.lilithgames.samo.android.cn:id/` 为前缀：

| 页面 | 控件 id | 语义／验证条件 |
| --- | --- | --- |
| 手机号 | `phoneEditText` | 填入后去除空格与请求号码核对 |
| 手机号 | `agreementCheckBox` | 检查 `checked`；用户明确确认协议后才勾选 |
| 手机号 | `submitButton` | 文案必须是「登录」；点击后发送验证码 |
| 验证码 | `digitsInput` | 六格自定义容器；点第一格并输入数字，满六位游戏自动校验 |
| 验证码 | `messageText` | 短信提示；对外只返回掩码号码 |
| 验证码 | `resendButton` | 倒计时期间拒绝重发，只接受「重新发送／重新获取／重发」文案 |
| 游戏 | `unitySurfaceView` | 只说明登录窗口已关闭，仍需主界面模板检查 |

登录检查沿用采集的城内（地图按钮 A/B）与世界地图（城堡按钮 A/B + 放大镜）模板，任一在自身阈值上命中即通过，不单靠放大镜。测试只使用手写的合成界面树，不提交真实 UIAutomator 导出或截图。

只读实机检查（开发者工具，不随安装包分发）：`npx tsx apps/wanlong-assistant/scripts/login-live-check.ts <实例编号> <模板目录>` 读取登录步骤并检查主界面；`--frame <PNG> <模板目录> [true|false]` 回放保存的画面。它不发短信、不输入、不启用任何自动任务。
## 脚本执行

脚本（`@avdm/automation/script` 的 JSON DSL）在独立的 `script-worker` 线程里执行，主进程通过设备 RPC 代为操作模拟器：每次输入前复核实例身份、绑定账号与前台包名，只允许启动或停止游戏自身（monkey 拉起并等待回到前台），中文文本需要实例上启用 ADBKeyboard。执行监控页可在任意已开机实例上临时运行脚本（账号可选）、暂停 / 继续 / 停止、查看实时日志与留痕截图（按留痕策略从最近一帧编码 JPEG，不额外截图）。全局同时运行的脚本默认最多 4 个；运行目录保留最近 200 次。
