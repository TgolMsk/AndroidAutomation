# 万龙觉醒 模板库说明

> 移植自旧版万龙面板。采集流程用的模板库，**当时在真机 2560×1440 原生截图上裁剪并逐张自检**（2026-09-09 起）。
> 参考分辨率 2560×1440。AVD 分辨率低于参考分辨率时 `prepareFrame` 会把帧换算到参考画布，**分数必须在当前 AVD 的真实画面上复核**；
> 建议把 AVD 建成 2560×1440（至少 1920×1080），否则数字字形（16~25px）在 960×540 上只剩 6~9px，识别可靠性没有保证。
> ★ 模板、真机截图属于用户本地数据，**不进仓库、不进安装包**；助手通过「导入旧版模板集（只增不改合并）」或模板库页自己裁。

## 0. 在哪、怎么用

| 项 | 值 |
|---|---|
| 模板集名 | **万龙觉醒**（用户自己的模板集） |
| 模板集 id | `<模板集ID>`（`tset_` + 16 位十六进制，助手新建时生成） |
| 磁盘位置 | `~/.avdm/automation/templates/wanlong/<模板集ID>/`（manifest.json + 每张一个 PNG），或用户选择的本地目录 |
| 模板总数（旧版） | **93**（界面模板 40 + 数字字形 53，分 7 套）；之后陆续补了资源统计、行内缩略图、透明底变体等 |
| 匹配算法 | `TM_CCOEFF_NORMED`，阈值 0.85，方差守卫 std ≥ 12 |
| 包名 | `com.lilithgames.samo.android.cn` |

加载（worker 里的标准写法，`@avdm/automation/wanlong`）：

```ts
import { loadGatherTemplates } from '@avdm/automation/wanlong'

// 界面模板按 shrink=2 编进 ui 表；带 digit 标签的字形按 shrink=1 编成字形集 ★
const templates = await loadGatherTemplates({ templateDir })
templates.require('tpl_btn_search')          // 界面模板（缺失抛中文错误）
templates.requireGlyphs('dig_dark20')        // 字形集
```

**★ 两个 shrink 不是笔误**：界面模板用 `shrink=2`（快，全屏 18ms）；数字字形只有 16~25px 高，
`shrink=2` 会把它们压到 8~12px，1/7、3/8、6/8 立刻糊在一起，**数字识别必须用 `shrink=1`**。
`matchTemplate` 强制 `tpl.shrink === frame.shrink`，所以帧也要各准备一份，或者只对数字 ROI 做 `shrink=1` 的小块灰度（`grayCropRef`）。
**模板集只编译一次**（worker 常驻复用 / 按目录缓存），模板库一变显式失效，绝不能每轮重编。

## 裁剪 / 自检工具

全部写入走正式通道（`TemplateLibrary.save`：std 守卫、原子写、同 id 覆盖），
命令行工具是 tplkit（`apps/wanlong-assistant/scripts/tplkit.ts`，开发者用 tsx 运行，子命令与旧版一致）：

| 子命令 | 作用 |
|---|---|
| `cap <name>` | 抓一帧原生 PNG + 一张 1280 宽 JPG 供人眼看 |
| `view <frame> x y w h <out> <zoom>` | 裁块放大，确认框选是否贴合 |
| `analyze <frame> x y w h [dark\|light] [thr]` | 算 std / 均值 / 前景紧致外接框 / **列投影分段**（切字形靠它） |
| `probe <frame> x y n` | 取 n×n 邻域 RGB 均值（开关态标定） |
| `glyphs ...` | 按列投影把一串数字自动切成单字并生成保存作业 |
| `save <jobs.json>` | 批量保存 |
| `verify <jobs.json>` | 正样本重匹配 + 负样本必须落空 |
| `cross <jobs.json>` | 同一套字形两两互匹（易混对自检） |
| `ocr <frame> x y w h pol thr <期望串> <套前缀>` | **跨场景识别自检**：切字→整套 argmax→与期望串比对 |
| `scan <framesDir> [前缀]` | **全量扫描**：每个模板在所有帧上匹配一遍，命中集合即验收依据 |
| `find <id> <frame> [roi]` | 单模板单帧匹配，用来算相对锚点的偏移 |
| `alpha ...` | 多帧差分去底预览（透明底模板） |
| `ls` / `del <前缀>` | 列出 / 删除 |

## 1. 验收口径（先看这里，否则会误判"不达标"）

### 1.1 正样本分数的**架构上限**不是 1.0

`packages/automation/src/vision.ts` 里模板降采样用的是 **cubic**，而参考分辨率的帧用的是**点采样**（`grayShrink`）。
这是刻意的取舍：点采样是"相位彩票"（对齐时 1.0000，错位时 0.7519 直接漏检），cubic 把四种相位全稳在 0.92~0.96。
**代价就是同帧重匹配也拿不到 1.0000。** 所以本库的验收口径是：

| 指标 | 要求 | 本库实际 |
|---|---|---|
| 方差守卫 std | ≥ 12 | **最低 23.2**（`dig_march_btn_colon`），界面模板最低 24.7 |
| 界面模板 正样本（**自己那一帧**重匹配，shrink=2） | ≥ 0.89 且远高于 0.85 阈值 | **0.899 ~ 0.995**，定位偏差全部 **0px**。最低的 `tpl_status_gathering_green` 0.899、`tpl_label_coord_row` 0.936 |
| 数字字形 正样本（自己那一帧，**shrink=1**） | ≥ 0.95 | **0.984 ~ 1.000**，定位偏差全部 **0px** |
| 跨帧 / 跨界面位置命中 | ≥ 0.85 | **0.864 ~ 0.997**。最低的三个：`tpl_status_gathering` 打在"进度条已变绿"的行上 0.864（这正是要配 `tpl_status_gathering_green` 做 anyTemplate 的原因）、`tpl_stamina_drop` 在召回后的帧上 0.908、`tpl_world_search_icon` 在换了地形的地图上 0.918 |
| 负样本 | `found === false` | **全部落空**，全库最高误命中 0.789 |

> 自帧重匹配覆盖了本轮新裁/重裁的 **36 张界面模板 + 18 张新数字字形**；
> 另外 4 张（`tpl_status_marching` / `tpl_btn_cancel` / `tpl_btn_confirm` / `tpl_dlg_title_notice`）
> 是上一轮遗留、本轮没有对应源帧，只做了跨帧扫描（见 §2 的说明）。
>
> 裁剪起点一律对齐到**偶数**坐标（`shrink=2` 的采样网格）。实测同一模板 y 从 829 改成 828，
> 正样本分数从 0.9359 提到 0.9709。tplkit 保存作业时会提示对齐。

### 1.2 数字用 argmax，不用阈值优先

同一套字形内部本来就相似（`6` vs `8` 互打 0.87）。所以读数必须是
**"在这个字位上，把整套字形都打一遍，取最高分"**，而不是"第一个超过 0.78 的就算"。
本库实测 argmax 余量（最高分 − 次高分）**≥ 0.139**，自匹配在 shrink=1 下是 1.000，余量充足。

### 逐条说明（只列需要注意的）

- **`tpl_btn_search` — 整个搜索面板唯一的锚点。** 面板随选中分类左右平移，五个页签实测模板中心 x：
  黑暗灵 **464** / 金矿 **855** / 伐木场 **1269** / 铁矿 **1697** / 魔水池 **2115**（y 恒 1055）。
  14 帧全命中、分数 0.967~0.987。**任何按钮坐标都必须由它的命中中心加偏移推出，绝不可写死。**
- **`tpl_btn_gather` — 资源点卡片锚点。** 真机复量：按钮矩形 x 1669..2011 / y 993..1104，
  **中心 (1840,1048)**，与"采集"二字墨迹中心重合。
  ⚠️ 旧文档的 (1819,1045) 来自 1280×720 缩放图，偏左 21px —— 已在 `gather-flow.json` 里整套重算。
- **`tpl_label_level` — ★"等级 N"标签随滑杆手柄移动**（见 §5.1）。必须先在整条滑杆行的宽带 ROI
  （`120,820 1500×56`）里匹配它，再取命中框右侧的窄条当数字 ROI。
- **`tpl_checkbox_auto_on` / `_off`** — 扫描里两者严格互斥：on 命中 11 帧、off 只命中 `s06_cb_off`
  那一帧（我特意点掉再点回来的那次）。判据仍以像素探针为主（§5.2），模板只作交叉校验。
- **`tpl_status_gathering` / `_green`** — 采集态的状态词是**白字压在载重进度条上**，
  进度条左段绿、右段灰，边界随采集进度右移会先后盖过"采""集""中"。所以要两张模板做 `anyTemplate`。
- **`tpl_status_gather_marching`** — 状态词实测是 **"采集行军中"**（5 个字），不是文档里写的"行军中"。
- **`tpl_status_returning`** — "返回中"。这是"采集完成后自动回城"的直接证据，ETA 调度的 `freeAt` 语义靠它成立。
- **`tpl_status_marching`（上一轮遗留）** — 在本轮 59 帧上 **0 命中**（最高 0.546）。
  它的 bounds 起点 x=1472，而本轮实测"采集行军中"墨迹起点是 1436，差 36px，疑似上一轮采到的是别的状态词。
  语义存疑，**请用 `tpl_status_gather_marching`**；本模板保留但不要作为主判据。
- **`tpl_btn_cancel` / `tpl_btn_confirm` / `tpl_dlg_title_notice`（上一轮遗留）** — 本轮未复现该对话框，0 命中。
  ⚠️ 但它们描述的机制是真的且很重要：**在世界地图上按 BACK 会弹"确定要退出游戏吗"，误点"确定"会退出游戏。**
  脚本关闭面板优先用"点面板外的空地"，只有在二级页里才用 BACK。
- **`tpl_alliance_tag_sample_<他方缩写>`** — ⚠️**不是本方联盟**，见 §5.4。仅用于验证"所属联盟"字段的 ROI。
- **`tpl_queue_icon_map`** — 世界地图右侧的队列徽章，**只在有队伍在外时才出现**，半透明叠在地图上。
  本轮只在一帧、一种地形上采到（std 31.6，命中 0.983）。想用它省掉一次开面板，**先在三种地形上复验**。
- **`tpl_label_coord_row` vs `tpl_label_coord_card`** — 两者高度相似：行内模板打在卡片上得 **0.957**（超阈值），
  反向只有 0.640。**必须靠各自的 ROI 区分**（行内 x 1080..1480、卡片 x 1600..2400），禁止全屏匹配。
- **`tpl_res_gold_title` vs `tpl_res_iron_title`** — 全库最紧的一对，互打 **0.789 / 0.792**（阈值 0.85 尚余 0.06）。
  四种资源标题两两交叉实测：金↔铁 0.789/0.792、木↔魔 0.683/0.700，都安全，但金铁这对要留意。

### 3.1 两套"通用"字形（**这是本库最省事的结论**）

游戏里同一号字体在多个界面复用，所以**不需要按界面各裁一套**，按"**字号 + 前景/背景极性**"分套即可：

| 套 | 长相 | 覆盖的界面 | 完整性 |
|---|---|---|---|
| **`dig_dark20`** | 21×29 深灰/黑字 压 浅色底 | ① 资源点卡片**储量**<br>② 部队管理表头**队列 N/M**<br>③ 部队管理行内 **采集行军中 / 返回中 的倒计时**<br>④ 创建部队页 兵力 / 负载量 | **完整** 0-9 : / , |

## 6.5 透明底模板（多帧差分去底）—— 会透背景的素材一律这么裁（2026-09-10 起的规矩）

圆环 / 镂空图标、半透明镜片、压在地图或城内地形上的按钮：整块裁的模板会随底下的背景漂移
（放大镜 0.79~0.985，兽族城内按钮 0.79~0.89）。做法：同一状态截 2~3 帧（把画面拖开一点再截），
差分后「没变」的像素才是控件本体，其余抠成透明、不参与匹配。

```bash
# 预览（洋红 = 抠掉）；tol 默认 24，覆盖率 <0.3 多半是几帧位置没对齐
tplkit alpha 22 1224 196 192 <预览输出.png> 24 <帧a.png> <帧b.png> <帧c.png>
# 正式裁：save 作业里加 diffFrames / diffTolerance，其余与普通模板一样
#   { "id": "...", "frame": "a.png", "crop": {...}, "diffFrames": ["b.png", "c.png"], "diffTolerance": 24 }
```

- 存盘后 manifest 里多一个 `maskCoverage`（不透明占比），模板列表显示「透明底 NN%」。
- 视觉层：PNG 带 α ⇒ `prepareTemplate` 生成掩码（std 只统计不透明像素）⇒ `matchIn` 走 OpenCV 带 mask 的 matchTemplate。
- 覆盖率 ≈100% 会自动退化成普通模板（实心控件不必去底）；<10% 或不足 64 像素会被拒绝。
- 已用透明底的模板：`tpl_nav_map_toggle_b`、`tpl_nav_city_toggle_b`、`tpl_world_search_icon`（跨阵营差分：兽族 3 帧 + 法师 2 帧）。
- 现场验证：助手里对一个实例执行「立即采样（只看不派）」或只读探针，看导航判据命中了哪张模板。
- **助手里也能做**：「模板库」页 → 抓一帧 → 拉截取框 → 「透明底」卡片里把游戏画面拖开一点再点「再抓一帧去底」（1~3 帧），
  右侧实时显示洋红底预览与不透明占比 → 保存。「模板 ID」留空自动生成，填已有 ID 则覆盖那张。

## 7. 补模板的标准流程（照做即可）

```bash
# 1) 导航到目标界面后抓帧
tplkit cap myshot

# 2) 放大看，确认要框哪里（不要框会变的数字/进度条/粒子光效/地图背景）
tplkit view <frames>/myshot.png 1500 600 700 600 <out>/x.png 2

# 3) 量墨迹紧致外接框；数字用列投影分段
tplkit analyze <frames>/myshot.png 1560 636 560 60 dark 60

# 4) 写 jobs.json（crop 起点务必对齐偶数），保存
tplkit save <jobs>/my.json

# 5) 自检：正样本 + 负样本
tplkit verify <jobs>/verify.json
tplkit scan <frames> tpl_        # 看命中集合对不对
tplkit ocr <frames>/myshot.png X Y W H dark 60 "期望串" dig_dark20   # 数字
```

三条硬规矩：

1. **crop 起点对齐偶数**，否则同帧重匹配会白掉 0.03~0.04 分。
2. **不要框会变的东西**：数字、倒计时、进度条填充、红点角标、金色按钮上的流光粒子、地图背景。
   （行军按钮那张模板高度必须停在 1275，再往下 12px 就是每次都不一样的倒计时。）
3. **裁完必做负样本**。只跑正样本看不出"恒返回命中"的低方差模板 —— std 守卫拦得住纯色，
   拦不住"在另一个界面上也有 0.9"这种误命中，只有换帧扫描才看得出来。
