## 关键设计结论
1. **面板位置随分类平移** → 搜索/加减按钮必须模板匹配，禁止硬编码。
2. **数字识别用 0-9 数字模板匹配**（游戏字体固定），比引入中文 OCR 更快更准；
   「采集者 无」用「无」字模板判定即可。
3. 派兵前置检查：行军队列 N/M 有空位、目标点采集者为无、储量与距离达标。
4. 「自动采集至清空」勾选后由游戏自己续采，脚本只需管派兵与回收，大幅降低轮询压力。
5. 「黑暗灵部队」分类独有的「自动」按钮 = 游戏内建自动打野，**清体力功能块应优先复用它**而不是自己造轮子。

## 等级策略
- 默认 `目标等级 = maxLv - 1`
- maxLv 每轮动态探测（滑杆拉满后读数），自动适应 8→10 的版本进程；上限**按资源**缓存
- 同级搜到的点被占用则重搜；连续失败 N 次自动降一级，直到 minLevel
- 可选：距离/储量阈值过滤，避免长途低效行军

# 架构原则 · 游戏内设置必须「对账」而非盲设
面板暴露的每一个游戏内设置项，脚本执行时必须走：
  **读取实际状态 → 与面板配置比对 → 仅在不一致时操作 → 操作后复验 → 复验不符则报错中止**
禁止「反正点一下就是了」的盲点写法（会把已经正确的状态点反）。

适用范围（当前已知）：
- 自动打野：目标类型、等级下限/上限、最低剩余兵力、宝物技能自动施放、**是否使用命令点道具**、派遣次数
- 资源采集：「自动采集至清空」勾选框 (1732, 922)

## 开关(toggle)状态检测 —— 用像素取色，不用模板匹配
实测两个开关（宝物技能 y=526、命令点道具 y=876）视觉规则完全一致：
| 状态 | 左半 probe (1993, y) | 右半 (2050, y) |
|---|---|---|
| 开 | 绿 RGB(58,187,50) | 白 (241,234,234) |
| 关 | 白 (241,234,234) | 深灰 (89,93,114) |

判定式：`probe` 处取 5x5 邻域均值，`g>150 && g>r+80 && g>b+80` ⇒ 开，否则关。
开关可点区域中心 = (2022, y)；probe 点 = (1993, y)。
优点：微秒级、不受缩放/抗锯齿影响、无需维护模板图。★ 必须取自裸帧（彩色），灰度帧拿不到颜色。

配置 schema 见 `packages/automation/game-data/wanlong/stamina-config.schema.json`（含全部控件坐标与 probe 点）。

# 【关键机制】搜索等级是「下限」而非「目标值」
游戏的搜索匹配规则：**返回等级 ≥ 搜索等级的资源点**，不是精确匹配。
> 例：搜 5 级，跳转到 7 级资源点，**这是正常且合理的结果**，不是异常。

## 对状态机的强制要求
1. **卡片等级校验必须是 `卡片等级 >= 搜索等级`，绝不能写成 `==`。**
   写成相等会在完全正常的情况下判为失败并触发重搜，导致**无限重搜死循环**。
2. 「等级策略」的语义随之改变：配置里的等级是**搜索下限（floor）**。
   - `maxLv - 1` 策略 = 把下限设为 maxLv-1，实际可能采到 maxLv 的点 —— 这反而是好事，收益更高。
   - 「降级重试」= **放宽下限**（下限调低会匹配到更多候选点），不是"退而求其次采低级点"。
3. 游戏**无法**搜索"恰好等于某等级"的点，也就**不存在等级上界控制**。
4. 因此卡片校验的真实判据是：`等级 >= 搜索下限` **且** `采集者 == 无` **且** 储量/距离达标。等级偏高不构成拒绝理由。

## 卡片字段「所属联盟」的取值与含义
资源点卡片的「所属联盟」字段**不只有「无」**，实测见过联盟缩写标签（示例 `[XYZ1]`），
表示该资源点位于某联盟的领地范围内。

### 【明确裁定】所属联盟**不作为采集判据** —— 任何领地的资源点都可以采
不要实现"跳过他方联盟领地"的过滤。该字段可以读取并在面板上展示（零成本，就在卡片上），但**绝不能因为它而拒绝一个资源点**。
（配置里保留了 `allianceTerritory`，默认 `any`；取其它值时本方缩写模板 `tpl_alliance_own` 必须按账号单独裁，缺失即降级为「只接受中立」。）

⇒ 卡片校验最终只有三项判据：
   1. `等级 >= 搜索下限`（注意是 >= 不是 ==）
   2. `采集者 == 无`
   3. 储量 / 距离达标

# 【最高优先级】采集功能块必须支持长时间无人值守挂机
实际用法是：**开启自动采集后离开，挂机数小时甚至过夜**。
所以验收标准不是"能跑通一次"，而是"**几小时内不需要人工干预**"。
这条要求高于功能完整度：宁可少一个可配置项，也不能有会卡死的路径。

## 1. 未知界面兜底恢复（最重要，缺了必然挂死）
每个步骤执行前后都要能回答"我现在在哪个界面"。一旦落到不认识的界面：
- 先尝试**通用关闭**：弹窗右上 × 模板（`tpl_btn_close_popup*`）→ 「取消」→ BACK 键（★ 紧跟取消退出框）
- 再问游戏资源更新处理器与 AI 顾问（见 游戏资源更新.md；AI 只执行关闭 / 取消且必须复验）
- 仍无法识别则执行**回家序列**：BACK 至多 N 次 → 校验是否回到城内/世界地图锚点
- 游戏不在前台则**冷启动**（只用 monkey 拉起，见下）并等待进入主界面
- 每一级恢复都要记日志，说明触发原因与恢复结果

## 2. 必须处理的干扰源（真实存在，挂机时一定会遇到）
- 活动推送弹窗、礼包弹窗、公告、每日签到
- 断线重连提示、网络异常提示
- 采集完成/被攻击的系统提示条
- 新版本 / 资源更新提示（资源下载弹窗有专门的处理器）
⇒ 需要一组「通用关闭」模板，作为**每个步骤的前置检查**，而不是只在出错时才处理。

## 3. 掉线与闪退检测
每轮循环开始时校验前台包名仍为 `com.lilithgames.samo.android.cn`；
不是则冷启动并等待回到主界面，再继续采集循环。不要假设游戏一直在前台。

## 4. 长跑的资源管理（挂机几小时会累积）
- **截图留痕必须自动清理或限流**（按 shotPolicy：默认只在失败时存，定期过期清理），否则磁盘会被撑爆
- 日志要滚动，不能单文件无限增长
- 长跑不得有内存泄漏：模板编译结果复用（**模板集只编译一次**，模板库变了显式失效）、帧 Buffer 及时释放、每个 OpenCV Mat 都要释放

## 5. 循环与停止语义
采集是**无限循环任务**，不是一次性脚本：
- 支持**优雅停止**：用户点停止后，当前步骤做完就停，不要在派兵中途硬中断
- 支持暂停 / 恢复
- 连续失败 N 次则**自动暂停该实例并在面板标红报错**，不要无限重试烧 CPU 和体力
  （队列满 / 没有想采的资源 / 放弃 / 体力不足 / 熔断**不是失败**，还要清零计数）

## 6. 挂机可观测性
用户离开时看不到过程，回来要能复盘：
- 面板要有历史记录：什么时候派了哪支队、目标坐标与等级、预计与实际完成时间、成功/失败原因
- 累计统计：本次挂机共派出多少队、各资源类型各多少次
- 异常要显眼（标红 + 原因），不要淹没在日志里

# 【实测】顶号与掉线的完整链路（2026-09-09 主动制造顶号后采集）

## 顶号全过程
```
账号在别处登录
  → 弹窗「注意 / 您已经在其他设备上登录了。/ 确定」   ← 稳态，不会自己消失
  →点「确定」(1275, 965)→ **游戏进程直接退出**到 Android 桌面（AVD 上是 com.android.launcher3）
  → 重启游戏 → 弹窗「注意 / 网络不稳定，连接已断开。请点击确定重新连接。(e12: MRF) / 确定」
  →点「确定」(1272, 899)→ 自动重连，**直接回到主城，无需重新输入账号密码**
```
⇒ 技术上可自动恢复。但**默认不要自动重登**：对方若仍在线会变成互相顶号的死循环。
   检测到顶号 ⇒ 暂停任务 + 推送通知。自动重登做成默认关闭的可选项。

## 启动游戏的正确姿势（重要）

  命令返回成功但进程起不来。

# 【游戏机制】抓宠次数在北京时间 0 点重置
野兽面板上的「持有: N」（实测为 5）是**每日捕捉次数**，在**北京时间 00:00** 重置。

## 对实现的要求
1. **复用唯一的北京时间实现**（`apps/wanlong-assistant/src/shared/time.ts` 的 `nextCstBoundary(now, 0)` 等）。
   **不要另写一套本地时间判断** —— 宿主机时区不一定是北京，这是最容易重新踩进去的坑。
2. **次数用尽时的调度**：不要盲目重试，把下次唤醒直接排到 `nextCstBoundary(now, 0) + 余量`。
   这和疲劳期开始是同一个时刻点，两者可以共用一次唤醒。
3. 次数要按「读到的实际值」为准（数字模板识别「持有: N」），不要靠本地计数推算 ——
   用户可能自己在手机上抓过几次，本地计数会漂。

## 与疲劳期的关系
北京 00:00 同时是：抓宠次数重置点 **和** 深夜疲惫期开始点（采集 −80%）。
排唤醒时注意两件事会在同一时刻发生，不要重复排两次唤醒。

# 【已修·真机验证】顶号检测原来只在采集周期里跑，队列满时永远不会触发
## 现象
配好 Telegram 后再次顶号，长时间没有暂停也没有推送。最终走了「连续 3 次采样失败」的通用兜底，
被归类成「掉线」而非「疑似顶号」，且第一次采样要等到下一个排定的唤醒（队列满时可能是几小时后的队列释放）。

## 根因
顶号探针只接在采集周期里；调度器自己的面板采样器认不出界面时另走一条路，不跑顶号探针。
队列 5/5 没有采集周期 ⇒ 精确识别从不运行。

## 修法（两条）
1. **采样失败路径直接跑探针**：采样器放弃前把最后那一帧交出来，用同一帧跑顶号探针，命中即暂停 + 推送。零额外截图，第一次采样就判定。
2. **健康探针**：`healthProbeIntervalMin`（默认 3，0=关）。到点只截一帧不开面板，
   跑顶号探针 + 前台包名 + 游戏进程存活（pidof）；进程没了 ⇒ `deviceOffline`。给检测延迟设上限，
   不再依赖队列释放的唤醒时机。
另：已暂停的实例不再累计采样失败、不再二次推送。

# 【已修·实测】部队管理面板行距是 243 不是 250（「五个队列只读出三个」）
现象：队列 5/5 时只识别出 3 行，第 4、5 行被当成空位。
根因：写死 `ROW_PITCH_Y = 250`，实测 5 行面板「坐标:」标签 y = 306/550/792/1036/1278，
行距 242~244。误差累积到第 4 行 20px、第 5 行 28px，状态词与「坐标:」标签识别带双双落空。
**不是**绿底进度条的问题：用真实行中心重打分，5 行全部命中 0.89~0.94（含绿底行）。
修法：`detectRowCenters()` 沿「坐标:」列扫描真实行中心；固定行距（243）只作空位兜底。

# 【多账号实测·已修】两条只有开第二个号才会踩到的坑（2026-09-10）
## 1. 部队管理入口只在有队伍在野外时才出现
一支队都没派 ⇒ 世界地图右侧栏是空的，入口图标不存在。盲点 (2522,592) 三次无反应，被误判成「模拟器或游戏掉线」并暂停实例。
修法：先匹配右侧入口图标 `tpl_queue_icon_map`，不在 ⇒ 判定 0 支队在外、返回空队列读数
（上限按配置估计，派兵后读真实值）。采集侧 `openTroopPanel()` 返回 boolean；★ 它**假定已经在世界地图**，调用前必须先 `ensureWorldMap`。

## 2. 不同阵营的 UI 美术不同（三套：法师 / 兽族 / 精灵）
游戏按阵营换整套建筑与按钮美术：**法师**（模板变体 A）、**兽族**（变体 B）、**精灵**（暂不适配）。
两态导航按钮（城内「切世界地图」↔ 世界地图「回城」）每个阵营各一套，法师号模板打在兽族号上只有 0.20~0.73：
- 世界地图判据 `WORLD_MAP_TEMPLATES` = anyTemplate(城堡A `tpl_nav_city_toggle`, 城堡B `tpl_nav_city_toggle_b`, 放大镜)；
- 城内判据 `CITY_TEMPLATES` = anyTemplate(地图钮A `tpl_nav_map_toggle`, 地图钮B `tpl_nav_map_toggle_b`)。
- 调度器采样、采集流程、资源统计预检三处判据统一用这两组。
⚠️ 以后每接入一个新阵营的账号，都要过一遍导航锚点模板；凡是依赖单一模板判定界面的地方都可能失效。

## 3. 透明底模板（多帧差分去底）—— 规矩：**类似素材一律去底再匹配**
兽族城内按钮是个白圆环，圆环里透着城内地形，城一拖动就变；整块裁的模板换个背景只有 0.79~0.89（阈值 0.85，随缘漏检）。
做法：同一状态截 2~3 帧（把画面拖开一点再截），差分取「没变」的像素当控件本体，其余抠成透明；
模板 PNG 带 α 通道 ⇒ 生成掩码 ⇒ OpenCV 带 mask 的 `matchTemplate`。
实测同一按钮：正样本 0.97~0.98（含没参与去底的帧），法师城内 0.63、世界地图 ≤0.50。
- 助手「模板库」页：抓一帧 → 拉框 → 把游戏画面拖开一点再「再抓一帧去底」（1~3 帧）→ 保存；列表里带「透明底 NN%」标签的就是这类模板。
- 适用：圆环 / 镂空图标、半透明镜片（放大镜）、压在地图或城内地形上的按钮、进度条会移动的状态词。
  不适用：整块实心控件（差分后覆盖率 ≈100%，会自动退化成普通模板，白跑一趟）。
